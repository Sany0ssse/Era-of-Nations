# Перевірка життєвого циклу членства ЄС

Запуск з кореня моду:

```powershell
python tools/validation/eu_membership/test_lifecycle.py
```

51 перевірка читають фактичні скрипти членства, тригери та callbacks національного духу `EU_member`. Обмежений інтерпретатор виконує їхній AST, а не копію логіки в окремому алгоритмі. Числові ідентифікатори країн з дробовою частиною зберігаються повністю.

Перевіряються дедуплікація реєстру, доступ незалежних живих учасників, втрата доступу й бюджетних залишків після виходу, тимчасове підпорядкування за наявності інших учасників, пауза інституцій без представників і заснування тільки за згодою точної пари. Вступ проходить заявку, одностайне схвалення кандидатства, переговорну паузу, всі урядові ратифікації, окрему згоду делегацій Європарламенту та остаточну ратифікацію кандидата. Просте схвалення не додає членство. Призупинення голосу уряду в Раді не скасовує його окрему національну ратифікацію: регресія виконує фактичні умови й complete_effect цільового рішення від призупиненого учасника та доводить, що його ратифікація лишається обов’язковою для вступу.

Для виходу перевіряються збереження прав до фактичного виходу, відкликання повідомлення, окрема згода Ради та Європарламенту, виключення держави, що виходить, і призупинених урядів із відповідного голосування Ради. Окремі голоси делегацій «за», «проти» й утримання змінюють згоду на угоду про вихід: потрібно більше голосів за, ніж проти, принаймні один голос за; утримання не входять у більшість. Для вступу зберігається більшість усіх активних місць. Частка населення рахується з поточних `state_population_k` власних регіонів. Перевірені прострочені відповіді, відкликана парламентська підтримка, неактивні делегації з застарілими місцями та очищення старих monitor missions, які раніше стирали голосування або повторно запускали таймери.

Це обмежені регресії, а не доказ роботи кампанії HOI4. `EU_update_vars`, старий повний `leaving_EU`, бюджетні розрахунки, призначення посад, скидання інституцій і native mission engine мають явно позначені межі: модель записує виклик або виконує тільки контракт очищення членства. Переобрання Європарламенту, парні ROOT/FROM події, запуск таймерів і зміни дипломатичного UI потрібно додатково перевіряти нативними пробами та в грі. Реальні збереження гравця ці тести не змінюють.

Правові джерела й відмінності між реальною процедурою та ігровими наближеннями описані в `docs/development/EU_INSTITUTIONS_UK.md`. Пороги реформ, 180-денна переговорна пауза, строки заявок і витрати політичної влади є балансуванням моду. Окремий виробничий цикл одностайного продовження строку Article50 та його 54 bounded перевірки й 12 mutation controls описані в tools/validation/eu_withdrawal_extension/README.md. Нативні природні строки й UI цього доповнення потребують окремої приймальної проби; поточні регресії їх не доводять.

Нативний парсер вимагає, щоб нові script TXT пакета були без BOM; EN/RU локалізація зберігає BOM. Регресія формату перевіряє обидва правила. Старі game files зберігають власний вихідний формат.

Нативні порівняння з іншим іменованим значенням записані через явні поля `var`, `value`, `compare`. У `for_each_scope_loop` фільтр є вкладеним `if`, оскільки сам цикл не приймає effect `limit`. Обидві межі захищені source contract регресіями.

Усі десять створень тимчасових прапорців членства явно задають value = 1 разом зі строком days. Це відповідає встановленим native game examples і захищене source contract та інтерпретатором регресій.

Фактичний вступ і вихід позначають зміну складу до мутації реєстру. Це запускає перерахунок місць і бюджету в центральному координаторі. Повторення callbacks не позначає новий перехід і не запускає зайві переобрання.

На початку заявки, ратифікації договору про вступ і погодження виходу інші активні учасники під керуванням людей отримують одне інформаційне повідомлення. Регресії перевіряють країну відправника, виключення ШІ та неактивних учасників і відсутність повторних повідомлень від повторення виклику. Кнопка повідомлення лише закриває його: голоси подаються через поточні рішення, тому старе відкрите вікно не може схвалити змінений договір. Реальне відображення повідомлень у мультиплеєрі потребує перевірки у грі.
