# Ракети та утримання арсеналу: перевірки

Запуск усіх поточних тестів цього пакета:

```powershell
python tools/validation/missile_system/run_checks.py
```

Ця команда читає поточні файли моду та виконує всі `test_*.py` з цієї папки й
папки `nuclear_arsenal`, включно з фактичним деревом скриптів утримання арсеналу.
Вона не запускає гру, не змінює збережень та не змінює ігрового джерела.

Прототип утримання вимкнений у поточному моді. Спільна модель готовності
читає фактичний `enabled = { always = no }` і повне дерево readiness:
старі safety/recovery значення не блокують запуск. Старі негативні кейси
режимів явно використовують `prototype_enabled=True` лише в тестовій моделі;
це не ввімкнення ігрової механіки. Запас, політика та придатність цілі
перевіряються в обох режимах.

- Дослідження: залежності спеціальних проєктів, ланцюги технологій, наявність
  дозволеного спорядження, спадкування моделей і приховані відкриття шахт.
- Застосування: точні граничні кількості, підготовка та повторна перевірка
  політики перед запуском, правильна область дії ефектів нальоту.
- Бюджет: нульова вартість вимкненого прототипу; в явно увімкненій моделі одна стаття тижневих видатків, тижневий прогрес до перерахунку та
  збереження єдиного стандартного платежу скарбниці. Окрема перевірка закупівель
  виконує фактичний ринковий блок шість разів у тому самому контексті: тимчасова
  сума обнуляється, попередній рахунок не множиться вдруге, ціни збережені.
- Збереження джерела: повна побайтова відповідність попередній версії поза
  точними вставками бюджетних викликів і скиданням тимчасової суми закупівель.
  Змінені або дубльовані вставки
  відхиляються, стороння правка не зникає з решти побайтового порівняння.
- Арктична ядерна кнопка: повна повторна перевірка початкових умов та готовності
  арсеналу; наслідки дозволені лише після оплати однієї ракети з одного запасу.
  Тести охоплюють заборони, зміну умов між показом і натисканням, відмову
  списання, порожній резерв і перехоплення. Початкове тіло пошкоджень та всі
  сторонні байти GUI перевіряються окремою точною оберненою заміною.
- Відкладена відповідь ШІ: виконавець і рівень зберігаються на цілі; сторонній
  місячний виклик та очищення глобальних змінних не перепризначають удар.
  Перевіряються перестановки країн, відмова оплати, застарілий результат і
  скасування старої черги без пари. Початковий глобальний контекст відновлюється.
- Арсенал: default-off, приховані категорія/рішення, нульова вартість і незмінні режими;
  в явно увімкненому прототипі резерв і розгортання, грошова формула, режими, чотири тижневі
  перевірки, захист від повторних викликів, відсутність подвійного платежу та
  відсутність списання реакторного урану. Навмисно зламані варіанти
  фактичного скрипту мають бути відхилені.
- Нативні квитанції: синтетичні позитивні та негативні приклади для читачів
  журналів; відхилення пропущених спостережень, неправильних областей дії,
  підміни хешів, прискорених тижнів і подвійної бюджетної статті. Читач лічильників
  також звіряє записані результати з числами спостережень, датами й фазами;
  слово `PASS` саме по собі не підтверджує позитивної кількості ракет.

Нативні кількості у скриптових тестах задані явно. Спільний AST-інтерпретатор
готовності використовується в запуску, оплаті, черзі та Арктиці. Облік
`num_equipment@` у цих тестах означає лише складський резерв: фізичний запас
у пускових не підміняє доступні для скриптової оплати ракети.
Успішний результат цих тестів не доводить фактичне завантаження шахти,
натискання кнопки користувачем, реальний наліт, ігрову кампанію чи мультиплеєр.
Нативні проби та їхні квитанції слід описувати окремо від цього результату.
Підготовка й читання окремої проби утримання описані в
[`nuclear_arsenal/README.md`](../nuclear_arsenal/README.md). Створення файлів
проби не запускає гру; синтетичний журнал у тесті не є журналом кампанії.

Історичні тести боргів використовують `byte_compat.py` лише для точного
вилучення дозволеної нової вставки перед порівнянням зі своїм старішим
еталоном. Вони не виконують «нормалізований» ігровий код: фінансова поведінка
продовжує перевірятися на фактичному поточному джерелі.
