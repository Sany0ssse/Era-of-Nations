# Перевірка початкового запиту про підтримку

База: `0747ce626b79bc7796d6fbb61be9cbf8a6076de0`. Цей пакет перевіряє чинну дипломатичну дію `AB_ask_foreign_support` та меню `AB_mobilization.4`. Код читається з поточного моду; попередні сценарії не запускаються під час імпорту визначень інтерпретатора.

```powershell
python -B tools/validation/diplomacy_package_22/test_request.py
python -B tools/validation/diplomacy_package_22/test_source.py
python -B tools/validation/diplomacy_package_22/run_checks.py
```

Окремі початкові регресії: `--focus request_replay`, `late_policy_loss`, `cooldown_bypass`, `unowned_decline`, `unowned_menu`, `multi_kind_handoff`. До змін кожна відтворювала помилку виконання фактичного коду; після змін кожна має пройти.

94 сценарії виконують поточний повний шлях: країна просить допомогу, постачальник отримує один запит на 30 днів, вибирає одну форму допомоги, запис запиту закривається перед передачею до окремого договору. Для грошей, обладнання й національного оборонного формування перевіряються також згода одержувача та чинне завершення виконання. Перевіряються повторні відповіді, свіжі політичні й ресурсні умови, неправильний партнер, декілька постачальників, один зайнятий слот постачальника, безкоштовне відкликання, строк, мир, пряма війна й обидва контексти анексії. Закриття нового початкового запиту не скасовує попередню пропозицію або оплачену службу.

28 перевірок адаптера охоплюють лише явні цілі невід'ємні залишки обладнання та межі історичного запуску, включно з явним дозволом незміненого `test_source.py` пакета01. Синтетичні збої перевіряють відновлення читачів, `subprocess`, повного `sys.path` та `argv`; вони не запускають і не додають до лічильника попередніх ігрових сценаріїв. Окремий свіжий процес перевіряє, що історичний режим запускається до завантаження поточних моделей. 164 перевірки джерел складаються зі 136 перевірок API та 28 перевірок меж байтових адаптерів. Чотири змінені файли відновлюються точно через чотири названі опції меню, два поля старої дії й один доданий захист та 12 рядків перекладу. Сім нових файлів, ідентифікатори, BOM та переноси рядків перевіряються окремо.

Збережено без зміни сирих байтів 53 попередні файли поведінки, допоміжні модулі й запускачі; загалом 74 попередні публічні файли поза журналами. У 20 старих перевірках джерел (02–21) змінено тільки явно записані маршрути читання й межі поточного пакета. Їхні початкові твердження та рядки лічильників збережено. Кожен повний журнал перевіряється на точне обернення й відхиляє сторонню зміну. Перед заморожуванням усі 20 старих перевірок джерел запускаються окремо.

## Явна межа історичної сумісності

Старі сценарії 18–20 починаються безпосередньо з опцій меню й не мають нового запису початкового запиту. Для них запускач явно викликає попередній запускач через `test_request.py --historical-caller`. Лише читання тексту трьох названих опцій `AB_mobilization.4.a/b/c` під час запуску трьох старих файлів поведінки отримує точні опції з наведеної бази. Усі дочірні допоміжні функції й договори залишаються поточними та незміненими. Відмова `.d`, решта подій, читання байтів і старі перевірки джерел читають чинні файли.

Дозволені старі скрипти перевіряються за сирими байтами або точним журналом. `test_source.py` пакета01 дозволений окремо лише за точного збігу сирих байтів із базою; він читає поточні файли й не має журналу змін. Невідомий шлях або вкладений запуск відхиляється; поточні чотири опції меню перевіряються за зафіксованими хешами перед проєкцією. Читачі відновлюються навіть після помилки. Звіт окремо містить фактичний хеш поточного `00_War_events.txt`, хеш історичного вигляду й хеши лише трьох історичних опцій. Поле `source_sha256` описує фактичні поточні файли; окреме `historical_caller_projection` описує виняток для виконання старого викликача.

Історичний CLI має окремий ранній запуск: він не імпортує поточний інтерпретатор пакета21 або його моделі. Папка дозволеного старого скрипту стає першим шляхом імпортів, як під час звичайного запуску Python, щоб локальні допоміжні модулі знаходились у власному пакеті. Після успіху й помилки відновлюються початкові об'єкти та повний вміст `sys.path` і `argv`. Свіжі історичні звіти явно містять `historical_bootstrap_current_models_loaded=false`.

Сумарні 7508 сценаріїв означають **94 поточні сценарії початкового запиту + 7414 сценарії попередньої сумісності**. Старі 7414 не доводять володіння новим початковим запитом. Машинний звіт позначає це як `prior_scope=unchanged_children_with_historical_AB4_caller_view`.

## Межі перевірки

Збережені 50 політичної влади є нативною вартістю дії; інтерпретатор не списує її за метаданими й не доводить фактичного списання або повернення грою. Строки 30/360 днів та одноденна черга є перевіреними деклараціями; плин часу задається явними умовами сценарію. Документація встановленої гри визначає ROOT як відправника й THIS як адресата. Поточна дія перевіряється також без FROM; передача до меню використовує ROOT постачальника та FROM заявника.

Виклики відправлення обладнання, списання запасів/людей та створення формування спостерігаються як непрозорі нативні команди. Запаси, люди, шаблони та частини не змінюються інтерпретатором. Це не доказ прибуття вантажу, створення частини, її комплектації або зіграної кампанії. Після нового запиту тій самій країні через 360 днів давнє вікно з тією самою парою може збігтися з новим записом; незмінний номер покоління нативної відповіді не відтворюється.
