# Продовження строку виходу з ЄС

```powershell
python -B tools/validation/eu_withdrawal_extension/test_lifecycle.py
python -B tools/validation/eu_withdrawal_extension/test_mutations.py
```

54 перевірки виконують актуальний виробничий AST, без підміни helpers або тестових підключень. Ще 12 mutation controls навмисно ламають AST лише в пам’яті й доводять, що суттєві помилки ловляться. Початкові RED та reviewed prototype receipts збережені в ignored `.local`, нативні107 докази не переписані.

Цикл: поточне повідомлення → проєкт продовження → адресні відповіді інших допущених урядів → окрема остаточна згода держави, що виходить → одна погоджена одиниця в черзі → її використання після фактичного закінчення чинного строку. Погодження не скидає залишок730 днів і не подовжує його одразу. Наступне продовження потребує нового проєкту. До фактичного виходу членство зберігається.

Усі допущені інші уряди повинні явно відповісти; відмова блокує згоду. Явне утримання представленого уряду не є відмовою, але відсутність відповіді не вважається його присутністю. Нуль допущених інших урядів не дає автоматичної згоди. Чинний реєстр і права голосу перераховуються до остаточного прийняття. Згода Європарламенту потрібна для договору про вихід, а окреме продовження строку її не потребує. [Стаття50](https://www.eeas.europa.eu/node/23842_en), [стаття235](https://eur-lex.europa.eu/legal-content/EN/ALL/?uri=CELEX%3A12016E235).

365 днів додаткового строку, 30 днів проєкту, 90 днів перерви й максимум одна невикористана згода є калібруванням гри. Вони не є законодавчо фіксованими величинами. Відсторонення права урядового голосу моделюється чинним `eon_eu_can_vote`; реальний обсяг правового рішення може відрізнятися.

Старі native missions зберігають свій реальний залишок: міграція не запускає нові730 днів. Main `EU_exit` має пріоритет над одночасним short clock. Callback до першого щоденного проходу теж враховується; відомий уже завершений старий строк не зависає. Повторення callbacks не витрачає згоду двічі. Для Article50 без будь-якого відомого clock дата не вигадується; фактичне відкликання залишається доступним і не позбавляє членства.

Перевірено очищення після відкликання, договору про вихід, no-deal, annex та інституційної паузи/перезаснування. Інформаційні вікна лише повідомляють про поточні рішення; OK не голосує й не погоджує застарілий проєкт. Новина про відкликання надсилається лише успішною дією відкликання, рівно один раз, а не generic mission remove callbacks.

`has_active_mission` та спливання flag days у bounded executor є явними контрольованими входами. `news_event` записує точний ID і scope виклику, а не відображає новину. Старий повний `leaving_EU`, бюджет, посади, native scheduler та існуючі API boundaries не симулюються. Це не доказ natural365/730-day кампанії, збереження після reload, multiplayer UX або злиття category definitions у native UI. Потрібна окрема нативна проба actual decision AST, ROOT/FROM, природного короткого expiry та старих native mission callbacks, зі збереженими source/fixture hashes і фактичним календарем гри.
