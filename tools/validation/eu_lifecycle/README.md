# Приватна нативна перевірка ЄС

Інструменти готують окрему фікстуру та перевіряють журнал HOI4. Вони самі
не встановлюють мод і не запускають гру. Попередні журнали й результати
не перезаписуються. Збереження гравця та підписані Workshop-файли не використовуються.

## Поточна фікстура v18

Повний CLI обов'язково додає Council і Parliament. Поточний склад містить 519 перевірок
у 145 прихованих подіях та дев'ять приватних файлів: 160 основних перевірок,
257 для виконання дій продовження виходу, 59 для EDU, 24 для Ради, 16 для Європарламенту
та три для природного щоденного призначення. Окрема діагностика цілей
альянсу не змінює ці лічильники. Початкові 144 умови, порядок та пояснення
збережені; їхній контрольний SHA звіряється під час побудови. Початкові 114
умов і природні межі строків продовження збережені. Початкові 41 умова EDU
залишаються окремим історичним контрактом v16: у v17 рівно дві перевірки
лічильників native hooks замінені новими явно оголошеними умовами підтвердження
створення та фактичної передачі керівництва. Решта 39 умов, 15 source handlers
і шість мінімальних строків EDU збережені. v18 зберігає всі попередні умови
та додає одну окрему перевірку вилучення: фактичний лідер AUS вилучає SWE,
а SWE має бути поза союзом із підтвердженим native leave cleanup до створення
стороннього союзу. Стару сумарну перевірку виконують після цього створення.
Два умовні cleanup adapters продовження завжди записують свої чотири перевірки,
навіть коли початкова умова Article50 хибна; ця умова збережена у gate виконання
source handler. Невиконана дія не може змінювати канонічний стан.
Єдина зміна попередньої core умови — очікуване значення версії фікстури 17→18.
Явні `build_v17` (518/145/9) і `build_v16` відтворюють старі методи;
їхні невдалі результати залишаються невдалими.
Історичний v15 має 568 умов, 141 подію та сім
файлів; його можна побудувати лише через явний `build_v15`.
Це склад сценарію, а не кількість уже пройдених нативних перевірок.

```powershell
python tools/validation/eu_lifecycle/build_native_probe.py --source "." --output ".local/eu-lifecycle/native-N" --authoritative-template
python -m unittest discover -s tools/validation/eu_lifecycle -p test_*.py
```

`N` означає новий номер приватного запуску. Самих команд недостатньо для
безпечного встановлення й запуску: основний процес окремо фіксує джерела,
порядок модів, документацію рушія, налаштування та фактичний процес гри.
Вихідний каталог має бути новим і приватним. `--authoritative-template`
дозволяє шаблон лише під `.local` чинного checkout, відхиляє junction та
збіг назв приватних файлів із виробничими. Шаблон не встановлюється у гру.

## Що є доказом

Аналізатор вимагає єдиних STARTUP/RUN_BEGIN/RUN_END, а для кожної умови —
впорядкованих BEGIN → PASS → END без повторів. Він звіряє фінальні лічильники,
обов'язкові спостереження, усі зв'язані SHA-256 та реальні дати гри.
Година24 нормалізується як наступний день00; неправильні календарні дати
не приймаються. Написаний у скрипті строк сам по собі не доводить, що він минув.

```powershell
python tools/validation/eu_lifecycle/analyze_native_probe.py --manifest ".local/missile-system/native-N/manifest.bound.json" --game-log "ШЛЯХ/game.log" --error-log "ШЛЯХ/error.log" --output ".local/eu-lifecycle/native-N-result.json"
```

`manifest.bound.json` прив'язує незмінний шаблон до фактичних заморожених
джерел та встановленої приватної фікстури. Початковий manifest збережений.
v16/v17/v18 відокремлюють authoritative `source_sha256` від `effective_source_sha256`.
Чотири явно оголошені файли мають приватні ваги AI=0 для тринадцяти рішень;
решта їхніх байтів, умови, ціни й complete_effect зберігаються. Оригінальні
чотири файли копіюються окремо поза mod і прив'язуються через `provenance_root`
та `provenance_sha256`. Аналізатор звіряє обидва стани й увесь AST, не
використовує змінений пізніше checkout як доказ старих джерел.
Зміна зв'язаного файла або нова пов'язана помилка відхиляє результат.
`--baseline-error-log` дозволяє відокремити лише точні старі повідомлення
успадкованих файлів із тією самою кількістю повторів. Помилки просторів
eon_eu/eon_edu та попередження про шість динамічних mission tokens завжди
фатальні, навіть якщо є в baseline. Це EU_exit, EU_exit_three_month,
обидві EU_voting_mission_focus_EUXXX_QMV_result та обидві
EU_parliament_focus_EUXXX_approve місії, включно з їхніми _timer варіантами.

## Заявлені входи й окремі межі

Основний склад: GER/FRA/ITA/HOL/SPR/CZE; POL проходить вступ і вихід,
NEP є сторонньою країною; EDU додатково використовує AUS/SWE/FIN.
Є фактичні ROOT/FROM події, окремі урядові та парламентські схвалення,
resident population weights, позитивні контролі доступу й офісних строків.
НАТО USA/POL потребує фактичного спільного членства й незмінного керівника;
позначка шаблону додатково потрібна лише з відповідним DLC. Відсутність DLC
не дозволяє обійти фактичні вимоги.

Продовження статті50 перевіряє нові та старі строки, явне утримання,
відсутню відповідь, відмову, повторне виконання та відкликання. У v16 позитивні
backend сценарії явно викликають точний source complete_effect за його передумовами.
Активаційні API спостерігаються лише в окремому негативному контролі; їхній
результат не запускає обхід і не є доказом натискання кнопки. Історичне припущення
v15 про бездіяльність кожної сирої активації не застосовується до v16.
`source_handler_runtime_contract` вимагає 30 справжніх парних
ROOT/THIS/FROM відповідей, зміну обраного лічильника рівно на1, незмінну
тотожність процедури й бездіяльний повторний callback. Ідентифікатори країн
зберігаються як непрозорі дробові токени; лічильники мають бути цілими.
Це перевірка виконання backend дії. Натискання GUI, автоматичний вибір
рішення AI та мультиплеєр цим контрактом не підтверджуються.

EDU виконує точний source complete_effect через явно заплановані події.
Позитивні дії перевіряють вихідні category/action gates, ROOT=THIS та цільовий
FROM. Два явні негативні callbacks перевіряють внутрішню відмову, а окрема
сира активація після завершення сценарію лише записує фактичний результат API.
У v17 рівно два фактичні constructor frames мають показати країну без фракції
перед native викликом, реальну фракцію й керівника після нього, ту саму країну
ROOT=THIS, зв'язаний attempt/generation/intent та чинний confirmation receipt із result1.
Це окремий метод від v16: відсутність native on_faction_formed чи
on_assume_faction_leadership записується чесно як діагностика. Їхні лічильники
не підробляються. Фактичний on_leave_faction залишається вимогою безпеки обліку;
доступ, згода на вступ, строки, розпуск і незмінність НАТО перевіряються далі.
Воєнна загроза є явним приватним входом через документований add_threat,
а не записом у readonly global.threat. Сирі передумови записуються до
калібрування. Фікстура не викликає faction hooks вручну; фактичні callbacks
рушія та source constructor мають показувати ту саму країну.

Рада має природні14-денні раунди, зміну голови, вакансію й перенесення
фактичного залишку старих місій. Європарламент має природний цикл
ЄП14д → Рада14д → повторний ЄП14д. Source callbacks виконуються як скрипти;
це окремо від доведеного GUI row scope чи автоматичного вибору кнопки AI.
Вузькі приватні on_daily hooks викликають саме виробничі capture/reconcile
helpers і залишають лічильники та слід виконання. Строки вручну не завершуються.

Щоденний світовий координатор ізольований на180днів протягом контрольованого
ланцюга; перед фінальним world scheduler блокування явно знімається.
Це тестовий вхід, не нова політика моду. Три фінальні перевірки потребують
природного14-денного призначення. Повний бюджет/MFF998/999, save/load,
кампанія2035, баланс, продуктивність, hotjoin та мультиплеєр не доводяться.

## Історія негативних результатів

Запуск108 завершив315 перевірок:228 PASS та87 FAIL. Після нього виправлені
входи тестів, синхронізація tokens і законодавчий цикл. Його журнал,
заморожений аналізаторv13 та негативний результат збережені без переписування.
Запуск107 мав144 PASS на попередніх джерелах і не є прийманням наступних змін.
Природне щоденне призначення голови ЄП у108 пройшло; це вузький позитивний
результат, який не закриває невдалі продовження чи EDU.

Попередні 563 перевірки21 джерельного набору належать до складу перед
виправленням кодування й v15. Штучні журнали contract tests і AST dry builds
не є результатами HOI4. Явні build_v14/build_v15/build_v16 зберігають старі контракти;
його негативні результати не перетворюються на позитивний backend результат.
Запуск109 зупинений як невдалий після parser errors у трьох нових EP файлах:
початковий BOM став окремим script/token identifier. 0із358 перевірок
виконано, RUN_END відсутній; 1132пов'язані повідомлення журналу й негативний
результат frozen v14 збережені. Це не приймання джерел або сценарію.
Документація activation API не обіцяє натискання кнопки або однакове виконання
complete_effect у всіх контекстах. У108 сирий EU_create_EDU залишив фактичний
CREATE_DECISION callback, тому універсальний висновок про бездіяльність API
був хибним. Перевірка handler runtime відокремлює source backend виконання
від спостереження API, GUI та автоматичного рішення AI.
Виправлення потребує нового запуску й власного суворого аналізу.
111 не запускали: його підготовку припинили після перевірки хибного припущення
про EDU activation API. Це не нативний позитивний чи негативний результат.
Запуск112 не пройшов початкове завантаження: 0із518 перевірок виконано,
670нових помилок фікстури; заморожені джерела, журнали й інструменти збережені.
Причиною був непідтримуваний запис `has_political_power >= 0` у приватному
контролі продовження; вузька заміна використовує `NOT = { has_political_power < 0 }`.
Склад v16 і початкові умови залишилися незмінними.
113 завершено з 436 PASS, 40 FAIL та 42 невиконаними перевірками з 518;
початкове завантаження пройшло, але перевірки продовження виявили
передчасні контрольні точки природних місій: 29/58 годин недостатньо
для всіх переходів денного таймера рушія. EDU створив реальну фракцію, але
native formation hook не підтвердив її облік. Невдалий 113 і заморожений v16
збережені; незалежні результати не переписуються новою фікстурою.
Для 114 контрольні очікування становлять 49 / 25 / 30 годин залежно від сценарію;
умови, калібрування і мінімум 24 / 48 годин аналізатора збережені. Новий метод v17
окремо перевіряє guarded confirmation після фактичного constructor return
та оголошену міграцію двох EDU умов, а не оголошує старі hook вимоги виконаними.
Запуск 114 / v17 очікує нативної перевірки; джерельні тести не є її результатом.
