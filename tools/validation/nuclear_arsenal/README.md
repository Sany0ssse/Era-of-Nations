# Утримання арсеналу: джерело та нативна проба

**Прототип вимкнено в чинному моді.** Старі прийняті квитанції83 стосуються
попереднього замороженого, увімкненого джерела. Наведений нижче builder готує
перевірку активного чотиритижневого циклу, а не перевірку вимкненого режиму.
Підготовка на чинному джерелі не вмикає механіку: маніфест явно записує
`source_disabled_by_constant_gate=true`, і нативні вимоги активного циклу
навмисно не пройдуть. Для нового досліду активного прототипу потрібна окремо
узгоджена тестова копія з явно ввімкненим gate. Builder сам gate не змінює,
а reader не послаблює попередні 132 вимоги приймання.

Скриптові перевірки запускаються разом із ракетним пакетом:

```powershell
python -B tools/validation/missile_system/run_checks.py
```

`test_source.py` виконує поточне дерево ігрових скриптів з явно заданими
значеннями штатних лічильників. `test_native_probe.py` перевіряє дерево й
нативну граматику підготовленої проби та відхилення неправильних журналів і
квитанцій. Журнали, PID та файл «виконуваного файла» в цих тестах навмисно
синтетичні. Вони перевіряють читач, а не запускають Hearts of Iron IV.

## Підготовка окремої проби

Цей інструмент тільки готує спостерігачі, приватну контрольну формулу витрат,
приватну копію тижневого обробника з журналюванням та `manifest.json`. Він не
запускає гру, не підміняє джерело моду й не змінює збережень. Для перевірки
підготовки на поточному джерелі можна використати нову порожню папку:

```powershell
python -B tools/validation/nuclear_arsenal/build_native_probe.py --source-root "E:\Era of Nations" --output "E:\Era of Nations\.local\upkeep-preparation-example" --prepare-only
```

Підготовчий маніфест позначений `preparation_only=true`; читач не прийме його
як нативний результат. Для фактичної ізольованої проби оператор має спочатку
створити заморожений експорт у новій папці та квитанцію цього експорту, а потім
вказати їхні справжні шляхи:

```powershell
python -B tools/validation/nuclear_arsenal/build_native_probe.py --source-root "<папка замороженого експорту>" --output "<нова папка проби>" --export-receipt "<квитанція експорту.json>"
```

Повторний виклик не перезаписує готовий маніфест. Без `--prepare-only`
інструмент відхиляє авторитетну робочу папку як джерело проби. Оператор
ізольованого запуску переносить файли з `mod/` проби до цього експорту;
оригінальні файли підготовленої проби зберігаються для порівняння хешів.
Спосіб запуску та квитанція процесу належать оператору; автоматичного запуску
в цьому інструменті немає.

`on_startup` призначає події для GER, FRA та RAJ у явних країнових областях.
Грошові й арсенальні ефекти виконуються всередині країнових подій. Події
додають лише приватний тестовий резерв, перевіряють повний і безпечний режими
та починають відновлення. Подальші спостереження читають чотири справжні
`on_weekly`; повторний виклик ефекту в тому самому імпульсі перевіряє захист
від передчасного завершення. Проба не переставляє дату кампанії.

## Читання результату

Після завершення окремої кампанії читач тільки читає наявні квитанції та
журнали:

```powershell
python -B tools/validation/nuclear_arsenal/analyze_native_probe.py --manifest "<папка проби>\manifest.json" --launch-receipt "<квитанція запуску арсенальної проби.json>" --game-log "<окрема userdata>\logs\game.log"
```

Квитанція запуску має `schema=1` та поля `pid`, `exe`, `exe_sha256`,
`source_root`, `manifest_sha256`, `embedded_fixture`, `embedded_root`,
`enabled_mods`, `user_dir`, `game_log`, `source_export_receipt_sha256`,
`start_receipt`, `process_start_utc` і `embedded_source_sha256`.
`start_receipt` посилається на початкову квитанцію процесу з тим самим PID,
виконуваним файлом, часом запуску та фактичними аргументами. Хеші беруться з
наявних файлів після підготовки; вигадані значення не є нативним доказом.

Читач звіряє джерело, вкладені спостерігачі, документацію рушія, експорт,
процес, окрему userdata, єдиний увімкнений мод та відповідні помилки рушія.
Версія проби 4 порівнює додаткові витрати за однакових поточних вхідних даних.
Контрольна формула є точною копією поточного `calculate_additional_expense_rate`,
з якої видалено лише три перевірені рядки нової ядерної статті. На кожному
спостереженні виконується чинна формула, контрольна формула і знову чинна
формула; різниця має дорівнювати саме поточній вартості арсеналу. Два виклики
чинної формули мають давати однаковий результат. Спостерігач відновлює
лічильник енергетичного доходу, який додатково змінює стара формула витрат.
Повний ВВП між цими трьома викликами не перераховується.

Це потрібно тому, що німецькі чинні субсидії залежать від ВВП на людину,
а повний економічний перерахунок змінює також його залежності. Проба записує
ВВП, його модифікатор робочої сили та обидві субсидії для окремої діагностики.
Вона не припускає, що весь наявний бюджет є незмінним при перемиканні режиму.
Приватні вставки журналювання показують порядок арсенального ефекту,
звичайного бюджету та звичайного платежу. Вони мають точне обернення; читач
звіряє всі інші байти тижневого файла з хешем замороженого джерела.

Грошова різниця множиться на мільйон перед порівнянням із цілими межами:
це запобігає округленню малого літерального допуску до нуля в рушії.
Старі невдалі журнали й квитанції зберігаються окремо. Читач зберігає
початкові суворі правила версії 3; нові правила версії 4 застосовуються
лише до нової підготовки та свіжого запуску й не перетворюють стару відмову
на успішний результат.

Для версії 4 потрібні всі 132 унікальні перевірки, 21 спостереження правильних
країн і 48 рядків виконання тижневого обробника в правильному порядку.
Потрібний порядок режимів та чотири тижневі спостереження з інтервалом
168 ігрових годин між послідовними тижнями. Перевіряються фактичні готовність,
залишок перевірок, кількості, ціна, заміна бюджетної статті один раз та
відсутність прямого платежу при перемиканні режимів. Після повторного виклику
в тому самому тижні прапорець захисту має бути видимим, а залишок відновлення
має залишатися незмінним. Відсутність такого захисту відхиляє результат.
Маніфест версії 4 прив'язує захист до точного блока `days = 6 value = 1`;
підготовка відхиляє джерело без явно заданого значення. Окрема нативна
діагностика встановила, що перевірена версія рушія записує тимчасовий блок
без `value` зі значенням нуль. Скриптовий тест використовує саме цю
спостережену поведінку та відхиляє мутацію, яка прибирає `value = 1`.
Допуск грошового
порівняння обмежений `0.000011` млрд для точності штатних змінних.

Успіх підтверджує саме ці спостереження для замороженого джерела. Приватно
доданий резерв не доводить дослідження, виробництво або ручне завантаження
шахти. Значення штатних лічильників перевіряються окремою ракетною пробою.
Цей результат також не підтверджує натискання гравцем кнопки нальоту,
фактичний запуск ракети, звичайну поведінку ШІ, збереження/завантаження чи
мультиплеєр. Перевірки гри не підтверджують реальні технічні процедури зброї.
